# ViewerGcode v0.5.0

## Настройки интерфейса и Demo

Кнопка «Настройки» открывает разделы GRBL, «Порт» и «Цветовая тема», включая работу без соединения. В разделе порта выбираются устройство и скорость; изменение доступно после разъединения. Скорость и тема (тёмная, светлая, Amber, системная) сохраняются в браузере. Тема применяется к фону, сетке и линиям визуализатора. ЛКМ вращает вид, ПКМ сдвигает его, колесо меняет масштаб. Настройки находятся в шапке, соединение — в терминале, отправка и сброс — над визуализатором. Команды станка расположены под Jog справа; коррекция скорости — внизу правой панели. Статистика доступна в раскрывающемся блоке «Сведения о программе».

В Demo `$$` читает параметры, а `$номер=значение` записывает их в имитируемую постоянную память (localStorage). Например, `$130=300` изменяет ход X, `$22=0` запрещает Home, `$10=0` переключает отчёт на WPos, `$20=1` включает проверку границ программных движений. Изменения доступны и через таблицу GRBL. Они переживают разъединение, сброс и перезапуск браузера на том же адресе. Электрические параметры STEP/DIR, ускорения, PWM и др. сохраняются и читаются, но физика этих параметров не моделируется.

В визуализаторе X/Y/Z/P показывают входы из поля `Pn` ответа `?`: «сработал», «свободен», «—» без связи. P обозначает щуп. На неподвижном станке состояние опрашивается 5 раз в секунду. В Demo доступны принудительные датчики; P также отображает успешное касание до отхода инструмента.

Новые сборки заменяют единственный запускатель `dist/v0.4.0/ViewerGcode.exe`: перед сборкой его процесс завершается, старый файл удаляется. Номер папки остаётся прежним, чтобы сохранялся путь запуска.

Локальное приложение для просмотра G-code и управления CNC-контроллером GRBL через USB/Serial. Работает в браузере, без внешних библиотек и облачной передачи программ.

## Запуск на новом компьютере

### Windows: запуск двойным щелчком

Скачайте **`ViewerGcode.exe`** из [последнего релиза](https://github.com/abukarenko/ViewerGcode/releases/latest) и запустите двойным щелчком. Запускатель содержит приложение, поднимает локальный сервер на `http://127.0.0.1:4173` и открывает браузер по умолчанию. Python и Node.js устанавливать не нужно. Готовый файл после сборки находится в `dist/v0.4.0/ViewerGcode.exe`; его можно скопировать отдельно на другой компьютер Windows x64.

Для связи с платой назначьте Chrome или Edge браузером по умолчанию либо откройте адрес сервера в одном из этих браузеров. USB-драйвер платы при необходимости устанавливается отдельно.

Запускатель работает в системном трее (значки возле часов). Двойной щелчок по значку открывает браузер; правая кнопка открывает меню: «Открыть браузер», «Показать запускатель», «Перезапустить сервер», «Выход». Крестик окна скрывает его в трей. Для полного завершения используйте «Выход» в меню значка. Закрытие сервера не отправляет команд остановки контроллеру.

**Автозагрузка Windows:** поместите EXE в постоянную папку, нажмите Win+R, введите `shell:startup` и создайте в открывшейся папке ярлык на EXE. В свойствах ярлыка добавьте после пути параметр `--tray`, например: `"C:\CNC\ViewerGcode.exe" --tray`. Сервер запустится после входа в Windows без открытия браузера. Открыть приложение можно через значок в трее. Подключение к плате остаётся ручным.

В окне запускателя можно изменить **«Порт сервера»** (1024–65535) и нажать **«Применить порт и перезапустить»**. По умолчанию используется 4173. Выбор сохраняется в `%LOCALAPPDATA%/ViewerGcode/launcher.json`, в том числе для автозагрузки. Если порт занят, окно остаётся открытым для выбора другого номера. При неудачной смене порта текущий сервер продолжает работать.

При смене порта браузер открывает новый адрес: тема, настройки Demo и разрешение Serial хранятся отдельно для каждого адреса. Перед сменой порта завершите работу с контроллером и сохраните редактируемую программу.

Для самостоятельной сборки установите Python 3.11+ x64 с Tkinter и выполните `powershell -ExecutionPolicy Bypass -File .\build-launcher.ps1` в корне проекта. Скрипт устанавливает PyInstaller в отдельное окружение `work/launcher-venv` и создаёт `dist/v0.4.0/ViewerGcode.exe`. Для установки сборщика нужен интернет. Исходный запускатель можно запустить командой `work/launcher-venv/Scripts/python.exe launcher.py` после установки зависимостей сборщиком.

### Альтернативный запуск из исходников через Node.js

### 1. Установите необходимое

- **Node.js 22 или новее** с npm: [официальный сайт](https://nodejs.org/). При установке на Windows оставьте добавление в PATH включённым.
- Настольный **Google Chrome или Microsoft Edge** с Web Serial.
- При необходимости — USB-драйвер вашей платы. В диспетчере устройств Windows плата должна появиться в разделе «Порты (COM и LPT)».

Git нужен только для клонирования; для ZIP-архива он не требуется. Python, компилятор, прошивальщик и `npm install` для запуска не нужны.

### 2. Скачайте приложение

Откройте [Releases](https://github.com/abukarenko/ViewerGcode/releases), скачайте `ViewerGcode-v0.5.0.zip` и распакуйте в обычную папку, например `C:\CNC\ViewerGcode`. Не запускайте изнутри архива.

Или клонируйте репозиторий:

```powershell
git clone https://github.com/abukarenko/ViewerGcode.git
cd ViewerGcode
```

### 3. Запустите сервер

Откройте терминал в распакованной папке проекта и выполните:

```powershell
cd cnc-viewer
node --version
npm start
```

Если PowerShell запрещает выполнение `npm.ps1`, используйте `npm.cmd start` либо запустите сервер напрямую:

```powershell
node server.cjs
```

Откройте **[http://127.0.0.1:4173](http://127.0.0.1:4173)** в Chrome/Edge. Оставьте терминал открытым. Для завершения сервера нажмите Ctrl+C в терминале. При следующем запуске достаточно снова выполнить `npm start`.

Сервер слушает только 127.0.0.1 — приложение доступно на этом компьютере. Для Serial используйте этот адрес, а не открытие HTML-файла двойным щелчком. Для просмотра без контроллера достаточно открыть `cnc-viewer/index.html`.

### 4. Соединитесь с контроллером

1. Подключите плату по USB. Закройте соединение с этим COM-портом в Candle, терминале или другом приложении.
2. В селекторе порта выберите **«Изменить порт…»**, затем нужную плату в окне браузера. Это выдаёт разрешение на доступ к устройству.
3. Выберите скорость, обычно **115200 бод**, и нажмите **«Соединить»**.
4. Приложение устанавливает DTR и RTS, ждёт запуска контроллера, читает `$$` и запрашивает `?`. После успешного открытия кнопка меняется на **«Разъединить»**.

При следующих запусках ранее разрешённый порт выбирается без повторного диалога, если браузер сохранил разрешение. Web Serial не сообщает номер COM: селектор показывает устройство и USB VID/PID. При нескольких одинаковых устройствах выбор может потребоваться повторно. Удаление разрешений браузера или другой профиль требует нового разрешения.

## Возможности

- Редактор G-code, загрузка `.nc`, `.gcode`, `.tap`, `.cnc`, `.txt`, перетаскивание файлов и сохранение.
- UTF-8, UTF-16 с BOM и распознавание Windows-1251 для старых CAM-файлов.
- Просмотр XYZ в 3D и проекциях XY/XZ/YZ; дуги G2/G3, IJK/R, винтовые перемещения.
- Поворот мышью, Shift + перетаскивание для сдвига, колесо для масштаба, двойной щелчок для вписывания.
- Пошаговый просмотр, диагностика и пропуск неподдерживаемых блоков по выбору пользователя.
- Serial: отправка программы, пауза, продолжение, сброс и журнал команд.
- Маркер инструмента по фактическим отчётам устройства, опрос с целевой частотой **35 Гц**.
- Рабочие и машинные координаты XYZ, расчёт через WCO, перевод дюймовых отчётов в мм.
- Jog XYZ: один клик — один относительный шаг, шаг 0.01–100 мм, подача 1–10000 мм/мин.
- Настройки GRBL с русскими пояснениями и расширениями [Mash3_grbl](https://github.com/abukarenko/Mash3_grbl).
- Коррекция рабочей подачи 10–200% и быстрых перемещений 25/50/100%.

## Работа с программой

Откройте файл, изучите диагностику и нажмите «Построить» после редактирования (Ctrl+Enter). «Отправить на станок» отправляет **весь текст редактора с первой строки**, независимо от выбранного кадра. Галка пропуска неподдерживаемых команд влияет только на предпросмотр, а не на отправку.

Передача покадровая: **строка → ok → опрос ? до Idle → следующая строка**. Это создаёт остановки между блоками; непрерывного заполнения планировщика в этом релизе нет. `ok` означает принятие команды. Пройденные блоки отмечаются отдельно от фактической позиции инструмента.

При ошибке или потере связи очередь останавливается; автоматического повтора строк нет. Ожидание `ok` ограничено 120 секундами, отдельного отчёта состояния — 3 секундами. Само движение и пауза могут длиться дольше. При медленных ответах частота опроса снижается без накопления запросов.

## Органы управления

| Кнопка / регулятор | Действие |
|---|---|
| Пауза / Продолжить | Команды `!` / `~` |
| Сброс GRBL | Отмена очереди, Ctrl-X, ожидание стартового сообщения, `$X`, проверка Idle |
| Jog X/Y/Z | `$J=G91 G21 …`; остановка кнопкой ⊘ или Esc (байт 0x85) |
| Ноль XY / Ноль Z | `G92 X0 Y0` / `G92 Z0`, изменение рабочих координат |
| Безопасный Z | `G53 G90 G0 Z0`, быстрый ход к машинному Z=0 |
| Щуп Z | Двойное касание, рабочий Z=0, подъём на 5 мм |
| Рабочая подача / Быстрый ход | Realtime-команды GRBL, подтверждение фактических процентов через `Ov:`; снятие галочки возвращает 100% |

«Безопасный Z» требует корректного машинного нуля: название кнопки не означает, что путь автоматически проверен на препятствия. Программный сброс не заменяет аппаратный аварийный выключатель. Закрытие браузера не гарантирует остановку станка.

### Щуп Z

Цикл по примеру Candle:

```gcode
G21 G91 G94
G38.2 Z-30 F100
G0 Z1
G38.2 Z-2 F10
G92 Z0
G91 G0 Z5
```

Перед циклом читаются `$G` и настройки. После успеха восстанавливаются единицы, режим координат, режим и значение подачи, исходный G0/G1/G80. Начальный G94 явно задаёт мм/мин. Режим дуги или probing перед запуском не допускается, поскольку его нельзя восстановить отдельной строкой без движения. При ошибке следующие команды не отправляются; временные режимы могут остаться активными. Толщина пластины не учитывается. В Mash3_grbl при `$7=1` probing запрещён.

### Параметры GRBL

«Параметры GRBL» читает `$$`. Редактируйте значения, проверьте список изменений и нажмите «Применить». После каждой записи ожидается `ok`, затем настройки перечитываются для проверки. При частичной ошибке показывается число подтверждённых записей. Параметры сохраняются в памяти платы.

В окне также доступны `$I` (версия), `$G` (режимы), `$#` (смещения) и `$N` (стартовые блоки). Справочник Mash3_grbl включает `$7`, настройки поворотной оси A и бит A=8 в масках направления и STEP. Неизвестные параметры не получают предположительных описаний.

## Ограничения первого релиза

- Предпросмотр и контроллер имеют разные возможности. G53/G54–G59/G92, probing, дополнительные оси и ряд коррекций не моделируются просмотрщиком, хотя контроллер может их выполнять.
- Визуализируется XYZ; ось A видна в исходном текстовом отчёте, но не в 3D.
- Нет проверки столкновений, снятия материала, кинематики и времени обработки.
- До получения WCO/единиц координаты могут отображаться как «—».
- Размер файла и количество строк не ограничены приложением; отправляемая строка — до 79 символов после удаления комментариев и пробелов.
- Собственный Windows-хост WebView2 и локальный Serial-мост не входят в поставку. Web Serial в таком хосте зависит от его поддержки.

## Если не запускается

| Симптом | Что проверить |
|---|---|
| `node` / `npm` не найден | Установите Node.js, откройте новый терминал, проверьте `node --version` |
| PowerShell блокирует npm | Используйте `npm.cmd start` или `node server.cjs` |
| `EADDRINUSE` | Порт 4173 уже занят; если сервер уже запущен, откройте его адрес |
| Нет платы в списке | USB-кабель с передачей данных, драйвер, диспетчер устройств, разрешение через «Изменить порт…» |
| Порт не открывается | Освободите его в другом приложении, проверьте USB-соединение |
| Тайм-аут GRBL | Скорость, прошивка, питание; кнопка соединения ждёт ответы `$$` и `?` |
| `Alarm` | Устраните причину; кнопка сброса выполняет Ctrl-X и `$X`, но не поиск машинного нуля |
| Старый интерфейс после обновления | Обновите страницу с Ctrl+F5 после остановки работы |

## Редактор программы

Над текстом доступны вставка, удаление, дублирование строк и переключение комментариев `;`. Команды работают с текущей строкой или выделенным диапазоном строк. Alt+Enter вставляет строку ниже, Alt+Shift+Enter — выше; Ctrl+D дублирует; Ctrl+Shift+K удаляет; Ctrl+/ переключает комментарий. Tab вставляет два пробела.

Ctrl+Z отменяет изменение, Ctrl+Y / Ctrl+Shift+Z возвращает его. Поле «История» позволяет перейти к любому номеру изменения, включая 0 — исходный текст. Число шагов не ограничено программно; история хранится в памяти текущей вкладки до загрузки другого файла или перезагрузки страницы. Новое редактирование после отката заменяет ветку возврата. «Построить» историю не очищает.

Ctrl+F открывает поиск без учёта регистра, Enter находит следующее совпадение с переходом в начало файла. Ctrl+G переводит фокус на номер строки; Enter выполняет переход. Текущая строка подсвечена, в панели показаны строка и столбец. Во время отправки редактор следует за отправляемой строкой и остаётся защищён от изменений; фокус кнопок управления не перехватывается.

### Модальный редактор и терминал

Кнопка «Редактор программы» в левой панели открывает большое модальное окно. Закрытие окна сохраняет текст и историю изменений; построение доступно внутри окна. Освободившаяся левая панель — терминал с журналом обмена, очисткой журнала и вводом одной команды. Enter отправляет, стрелки ↑/↓ выбирают предыдущие команды текущей сессии. Поддерживаются обычные G-code и системные `$`-команды; `?` выводит состояние. Во время программы, Jog и других операций отправка из терминала блокируется. Пауза, продолжение и сброс остаются отдельными кнопками. Команды терминала исполняются на устройстве и не добавляются в программу редактора.

### Контекстное меню

ПКМ открывает меню приложения. В редакторе доступны история, буфер обмена, операции над строками, поиск и построение. В терминале — копирование выделения или журнала, очистка и переход к вводу команды. На траектории — проекции, вписывание, сетка и быстрые ходы. Меню управляется стрелками, Home/End, Enter и Esc. Браузер может запросить разрешение на буфер обмена; при отказе остаются обычные Ctrl+C/X/V. Машинные команды через контекстное меню не отправляются.


## Карта высот (v0.4.0)

Для знакомства без платы нажмите «Демо-карта», затем «Применить коррекцию» на встроенном примере программы. Это искусственная поверхность; отправка активной демо-карты заблокирована.

Кнопка «Карта высот» открывает модальное окно с областью XY, сеткой, опорной точкой, верхним и нижним рабочими Z и подачей щупа. «По границам программы» заполняет прямоугольник по траектории. «Взять текущие X/Y» выбирает опорную точку. «Перейти к опорной точке» сначала поднимает инструмент до верхнего Z, затем перемещает XY; команда задаёт G21 G90.

Перед измерением нужны Idle, остановленный шпиндель (M5), исправный разомкнутый щуп, доступные рабочие и машинные координаты. Для Mash3_grbl режим $7=1 несовместим с измерением. Верхний Z должен обеспечивать свободный переход над всей деталью; нижний Z — абсолютная рабочая граница поиска поверхности.

Измерение сначала снимает опорную высоту, затем проходит сетку змейкой. Координаты берутся из успешных ответов PRB. После каждого касания инструмент поднимается. При ошибке/потере связи/нажатии «Остановить» очередь прекращается без автоматического отхода и продолжения; требуется восстановить состояние контроллера. Частичную карту можно сохранить, но применить нельзя. Продолжение частичного измерения пока не поддерживается.

Карта отображается цветом с минимумом, максимумом и перепадом Z. Формат `.heightmap` — JSON ViewerGcode версии 1, с сеткой, значениями и привязкой рабочих координат; это не формат `.map` Candle. После измерения выставьте точный рабочий Z0 касанием поверхности в опорной точке (перейдите к ней, закройте окно карты и используйте «Щуп Z»). Привязка Z при отправке проверяется относительно измеренной опорной поверхности с допуском 0.005 мм. Изменение закрепления детали, инструмента или машинного отсчёта требует нового измерения.

«Применить коррекцию» сохраняет исходник в памяти и заменяет программу и предпросмотр скорректированным кодом. «Вернуть исходник» отменяет коррекцию. «Сохранить G-code» экспортирует результат. Не редактируйте исправленный код перед отправкой: верните исходник, измените его и примените карту заново. Оригинал и активная карта в памяти теряются после перезагрузки страницы — сохраняйте файлы.

Первый вариант коррекции рассчитан на явные G21 G90, G94 и дуги в XY; исходный G-code должен проходить строгий разбор. Смена инструмента, смещений, дюймы, относительные перемещения и другие плоскости отклоняются. В начале нужны G0 Z на высоту не ниже верхнего Z карты, затем явные X и Y. Быстрые ходы ниже верхнего Z отклоняются. Используется билинейная интерполяция; рабочие движения разбиваются по заданному максимальному шагу, дуги переводятся в G1 (допуск исходного разбиения 0.02 мм). Высота быстрых ходов не корректируется; перед переходом XY выводится отдельный подъём Z. Рабочая траектория должна целиком лежать в пределах карты.

Перед отправкой активной исправленной программы проверяются рабочая система G54–G59 и смещения XYZ. Экспортированный G-code, открытый отдельно, является обычной программой и не несёт автоматической проверки привязки карты.

Проверки карты выполнены на имитаторе GRBL; испытания щупом на реальном станке ещё не проводились.


### Home, состояние и очередь Jog

Home отправляет `$H` и ждёт завершения поиска машинного нуля. Площадка XY под траекторией показывает состояние: Alarm — тёмно-красный, Hold/Door — жёлтый, Run/Jog/Home — синий, Idle — зелёный. При отключении площадка скрывается.

Кнопки Jog принимают до пяти нажатий вместе с выполняющимся. Каждое сохраняет свой шаг, ось и подачу; следующее начинается после Idle. Стоп/Esc, сброс, ошибка и отключение удаляют ожидающие перемещения.


### DEMO — имитатор станка

`G43 Hn` принимается с явным сообщением о нулевой коррекции длины: таблица длин инструментов в Demo пока отсутствует. Движение в том же блоке выполняется, режим отражается в `$G`; `G49` и сброс отменяют его. Это не моделирование реальной длины установленного инструмента.

Команды `Tn` и `M6` поддерживаются как виртуальная смена инструмента: Demo выводит сообщение и сразу продолжает программу, без изменения длины инструмента. Команды реальной плате отправляются без изменений.

После Home выберите вид XY и перетаскивайте модель левой кнопкой мыши. Размещение ограничено границами стола и доступно в состоянии Idle. Меняется рабочий ноль симулятора, поэтому последующая обработка следует новому размещению; текст G-code остаётся прежним. Shift + перетаскивание сдвигает вид. При активной коррекции по карте высот перемещение модели недоступно.

В терминале подтверждение `ok` и ответ `error:…` дописываются в строку отправленной команды.

Включите Demo слева от G0 и нажмите «Соединить». Используется виртуальный Serial-порт внутри браузера: разрешение COM-порта не запрашивается. Переключение Demo/плата доступно после разъединения.

В «Параметрах GRBL» появляется блок имитатора: скорость времени, высота и неровность поверхности, исправность щупа и датчиков X/Y/Z, принудительное замыкание. Датчики можно переключать во время движения, открыв это окно; запись обычных параметров в это время заблокирована. При включённом $21 срабатывание концевика даёт Alarm 1. Для восстановления разомкните датчик и выполните сброс GRBL.

Home ($H) проверяет $22, ищет Z, затем XY, отходит на $27; $23 задаёт направление. Неисправный датчик приводит к Alarm 9, принудительно замкнутый — к Alarm 8. Размеры пространства задаются $130–$132. Начальная машинная позиция 50,50,15 мм, рабочая 0,0,5 мм. Диапазон машинных координат имитатора положительный: 0…размер оси.

Поддержаны G0/G1, дуги XY, Jog, пауза/продолжение, сброс, G92, G38.2, базовые запросы GRBL и overrides. Это модель для проверки интерфейса и последовательности команд, без физики ускорений, электрического дребезга и точного воспроизведения всех режимов прошивки. Параметры GRBL имитатора и его настройки (скорость времени, поверхность, исправность и принудительное состояние датчиков) автоматически сохраняются в localStorage браузера и восстанавливаются при следующем запуске. Данные привязаны к профилю браузера и адресу приложения; очистка данных сайта удаляет их. Координаты и выполняющееся движение не сохраняются.


### Восстановление рабочего нуля

Кнопка «К центру» сначала поднимает инструмент до рабочего Z, выбранного рядом (1/5/10/20 мм), затем перемещает в рабочий X0 Y0. Если текущий Z выше выбранного, он не опускается. Оба движения выполняются G1 с подачей из поля Jog; перед XY контроллер должен подтвердить завершение подъёма. X0 Y0 — заданный вами рабочий ноль, а не вычисленный геометрический центр модели.

«Шаг, мм» допускает ручной ввод: любой нецифровой символ преобразуется в точку (`23,45` и `23-45` → `23.45`). Сохраняется ограничение одного шага Jog до 100 мм; несколько разделителей дают ошибку ввода. Подача автоматически сохраняется в localStorage текущего браузера и восстанавливается после перезапуска.

После успешного G92 (кнопки «Ноль XY», «Ноль Z», щуп или команда в терминале/программе) приложение автоматически запоминает рабочий ноль по свежим машинным и рабочим координатам. Кнопка «Вернуть ноль» восстанавливает его командой G92 без движения осей; учитываются текущая позиция и режим G20/G21. Это позволяет после сброса в Idle продолжить работу без повторного подвода инструмента к заготовке.

Память действует в пределах текущего подключения. Сброс во время занятого состояния или движения очищает её, поскольку привязка машинных координат может быть потеряна. После отключения/включения платы рабочий ноль нужно задать заново.

В редакторе «Игнорировать неподдерживаемые команды» включено по умолчанию. Это настройка построения: весь блок с неизвестной G/M-командой пропускается в визуализации. При отправке контроллеру исходные команды сохраняются, а `error` по-прежнему останавливает отправку.

### Экспорт параметров GRBL

В окне «Параметры GRBL» нажмите «Экспорт .nc». Для платы перед экспортом читаются актуальные `$$`; для Demo сохраняются параметры виртуального контроллера. Файл содержит строки `$номер=значение`, отсортированные по номеру. Несохранённые правки полей в экспорт не входят — сначала нажмите «Применить». Это файл команд настроек, а не траектория обработки; автоматический импорт настроек пока не реализован.


После успешного Home (кнопка или `$H` в терминале) визуализатор читает $130/$131/$132 и показывает рабочий объём красным пунктиром. Используются машинные границы стандартного GRBL/Mash3_grbl: от минус хода до нуля; в Demo — от нуля до положительного хода. Для прошивок с HOMING_FORCE_SET_ORIGIN эта привязка не подходит. WCO переводит контур в рабочие координаты. Контур служит ориентиром и не заменяет программные пределы контроллера. Сброс и отключение скрывают контур до следующего Home.

Таймер над визуализатором показывает время программы от запуска до завершения, включая паузы. Между программами каждый Jog запускает отдельный отсчёт. RESET, ошибка или отключение останавливают таймер; результат остаётся видимым. Цветной индикатор отображает IDLE / RUN / PAUSE / ALARM.
